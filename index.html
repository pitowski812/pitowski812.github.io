Peptide① — production SaaS + iOS App Store app

Founder / sole builder · Flask · Capacitor (iOS + Android) · StoreKit 2 · Stripe · SQLite + Litestream · Northflank · Cloudflare

A peptide-education platform: research library, dose calculator, guided planners, nutrition and activity tracking, community forum, and an AI research assistant — on the web, as an iOS App Store app (released July 2026) with auto-renewable subscriptions, and as an Android build with web billing.

  • Navigated real App Store review to approval.   • Refactored under load: split a 12,900-line Flask monolith into 15 domain blueprints (−57% in the core file, 161 routes).
  • Operated like a team: worktree-isolated branches, PR pipeline with 7 CI checks (pytest ~2,200 tests, ruff, pyright, pip-audit, security review), staging → production promotion with verified deploys, continuous SQLite replication to object storage.

Pep①Ai — RAG chatbot with semantic search + fail-closed safety architecture

Designer / builder · semantic search (hybrid BM25 + vectors + rank fusion) · local embeddings · multi-stage safety gates

A domain research assistant grounded in a curated evidence corpus (PubMed ingestion, community sources, audio-transcript pipeline via Whisper) — built for a domain where a wrong answer is a safety problem, not a typo.

  • Three-state safety contract: every checker distinguishes passed / blocked / checker-unavailable — an internal guard failure can never masquerade as “no violation found.” Deterministic guards down → the answer is withheld with a distinct degraded message; outages log greppable markers for alerting.
  • Defense in depth: pre-generation intent screening, deterministic bounds checking on generated numbers, claim-level faithfulness gating with a different-vendor LLM judge (and a circuit breaker so a judge outage reads as an outage, not a verdict).
  • Evidence transparency: formal literature and community-reported practice are separate, labeled lanes with exact attribution — community signal is preserved but never silently promoted to clinical fact.
  • Caught its own failure in production: found and fixed a case where the grounding guardrail was failing open, then added tests that force each guard to fail and assert the answer is withheld.
  • Evaluated, not vibes: frozen retrieval benchmark + a 50-case answer-quality golden set judged by a different model vendor; route-level exception-injection tests prove the failure behavior.

Multi-agent AI operations ecosystem

Architect / operator · Claude Code · Codex · MCP · local LLMs (Ollama/LiteLLM) · launchd automation

The infrastructure that builds and runs everything above: a governed fleet of AI agents with one orchestrator, specialist engines, and mechanical guardrails.

  • Governed orchestration: ~30 specialized agents (builders, adversarial reviewers, compliance gates) with least-privilege tool grants; cross-vendor verification doctrine — model reviews find errors, deterministic tests certify truth.
  • Reusable workflow engine: parallel build waves with file-ownership preflights, mechanical exit-code test barriers, and adversarial SHIP/BLOCK review — failure propagation proven by injection tests.
  • Self-operating: 30+ scheduled jobs — deploy watchers, DB snapshots, nightly retros, a daily fleet-health report to Telegram.
  • Mechanical guardrails, not promises: 26 lifecycle hooks — a shell-command guard, secret scanning on every file write and command output, per-file lane locks so parallel agents can't collide, and a verify-before-stop check that blocks "done" without real output. A structured mistake log (~450 entries) feeds nightly retros back into the rules.
  • Marketing automation, end to end: AI-generated educational graphics and reels, auto-captioning, a platform-aware compliance linter (per-network claim rules), API scheduling to Instagram, and a nightly engagement-analytics feedback loop that steers what gets produced next.

Local LLM stack — private inference, routed by role

Builder / operator · Ollama · LiteLLM · custom MCP server · LanceDB · n8n

A self-hosted inference layer on a Mac Studio (M3 Ultra, 96 GB) so bulk AI work runs locally and privately, and the expensive frontier model is reserved for judgment.

  • Two warm local models, chosen on data: a fast mixture-of-experts Qwen model for bulk work and a dense Qwen model for reasoning. An in-house thinking-mode eval picked the reasoning model (30/30 vs 29/30) at 3–4× less wall time.
  • One router, many models: a LiteLLM gateway exposes role-named aliases (local worker, local reasoner, cloud coder, cloud reasoner) behind a single OpenAI-compatible endpoint, so tools switch models by changing a name, not code.
  • Custom MCP server for delegation: lets the orchestrating agent hand work to local models — coding, long-context map-reduce summarization, background jobs, sandboxed code execution, and semantic search — and collect the results.
  • Personal RAG: LanceDB vector index over a ~2,000-note knowledge base, split into separate indexes by domain, with local embeddings (embedder choice A/B-tested before committing).
  • Workflow automation: self-hosted n8n wired to the local models for scheduled pipelines.

Agentic Client Kit — secure starter for client AI builds (open source →)

Author · Claude Code skills · MCP · Microsoft Graph · NetSuite REST/SuiteQL

A reusable kit for building AI agents and workflows inside a client's own environment, on the client's Claude account, so client data never leaves their walls.

  • A repeatable engagement method: discovery → scope → access request → build → security review → test → handover, with a human approval gate at each step and fill-in documents for every phase.
  • Least privilege by default: playbooks for Microsoft 365 (Sites.Selected, scoped mailboxes) and NetSuite (view-only custom role, sandbox first); Claude is blocked from reading secret files and must ask before pushing code or reaching the network.
  • A go-live security gate: permissions, secrets, data handling, prompt-injection tests, logging, and a kill switch, each recorded PASS/FAIL with evidence.
  • Working example: a read-only SharePoint MCP server scoped to one site that returns metadata, never file contents, with input validation and throttling handling.
